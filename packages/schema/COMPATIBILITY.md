# ATCN schema versioning and compatibility (IN-9)

Wire `schema_version` `"1.0"`; obligation terms `"1.0"`, `"1.1"` or `"1.2"`; agent traces `trace_version` `"1.0"`. Every package in this repository shares one version; the first public release was 1.3.0. Earlier package versions were never published. Published JSON Schemas: [`schemas/1.0/`](schemas/1.0/), [`schemas/1.1/`](schemas/1.1/) and [`schemas/1.2/`](schemas/1.2/) (which adds `agent-trace` and `usage-summary`). Signing vectors: [`test-vectors/vectors.json`](test-vectors/vectors.json). Adversarial attestation fixtures: [`packages/verifiers/test-vectors/attestations.json`](../verifiers/test-vectors/attestations.json). Trace and pricing vectors: [`packages/sdk-ts/test-vectors/traces.json`](../sdk-ts/test-vectors/traces.json).

## Versioning rules

- The wire `schema_version` uses `MAJOR.MINOR`. The npm/PyPI package uses semver `MAJOR.MINOR.PATCH`.
- **PATCH:** documentation, examples, and validation messages. No wire change.
- **MINOR:** additive only. New optional fields, new event types, new account types, new enum members in *outputs*. Producers on `1.x` must not emit fields that a `1.0` consumer would need in order to verify a signature or recompute a decision.
- **MAJOR:** any change to required fields, field meaning, the canonicalization rules, the signing input, the decision digest inputs, or the journal balance semantics.

## Consumer rules

- Verify signatures over the **exact received payload**. Never re-serialize after dropping unknown fields.
- Ignore unknown optional fields when validating, but keep them when storing or forwarding.
- Reject events whose `schema_version` major differs from the supported major.
- Decision digests are recomputed with the clearing-engine version recorded in `decision_maker.id`. A newer engine must produce identical digests for decisions made by older engines, or must be registered as a new `decision_maker.id`.

## Canonicalization and signing (stable within major 1)

- Canonical JSON follows RFC 8785 (JCS), restricted to strings, booleans, null, arrays, objects, and **safe integers**. Floats are rejected, and amounts are integer minor units.
- Object keys are ASCII and sorted by UTF-16 code unit.
- The signature is Ed25519 over the UTF-8 bytes of `canonicalize(payload)`, encoded as base64url without padding.
- The payload hash is `"sha256:" + hex(sha256(canonicalize(payload)))`.
- Webhook signatures are Ed25519 over `"<unix seconds>.<raw body>"`, sent in the header `ATCN-Signature: t=..,key_id=..,key_version=..,sig=..`.

## Runs, skills, and attestation expiry and revocation (1.4.0)

- **Terms `schema_version` `1.1`** adds the optional `skill` (`{namespace, skill_id, agent_card_url?}`). Terms that set `skill` must declare `1.1`, because a 1.3.x `@atcn/core` would drop the field and then fail the effective-terms digest. Terms without `skill` stay `1.0`, byte for byte. `buildTerms` picks the version.
- **`obligation.started` data** may carry `execution`, the run descriptor: `execution_id`, the A2A task and context ids, the agent's own id, version, agent card digest, model and config digest, and the skill. Event `schema_version` stays `1.0`, because event `data` is an open record that older consumers keep and sign as received. The service and local runner require `execution.agent.agent_id` to be the signing agent, and require the agreed skill when the terms name one.
- **External attestations** gain optional `execution` (`{execution_id, execution_digest}`, the digest of the descriptor), `evidence_digests`, `issued_at`, `expires_at` and `refs` (`revokes` or `disputes` an earlier attestation by payload digest). `issued_at` is required with `expires_at` or `refs`. They are read by the new verifier `external_attestation@1.1.0`. `1.0.0` is unchanged and ignores them, so a policy opts in by pinning `1.1.0`.
- **`external_attestation@1.1.0`** refuses, with a `code` in the result details: a malformed attestation (`malformed`), a different subject (`subject_mismatch`), an unagreed verifier (`verifier_not_agreed`), a key that is not the verifier's (`key_not_verifier`), a bad signature over the payload as received (`signature_invalid`), a key revoked at or before `issued_at` (`key_revoked`), an expired or future-dated attestation (`expired`, `not_yet_valid`; 5 minutes of clock skew), a run the counterparty did not declare (`execution_not_declared`), a run of another skill (`skill_mismatch`), no run when the terms name a skill (`execution_required`), and evidence not submitted on the obligation (`evidence_not_on_obligation`).
- **Revocation.** Only the original signer can revoke. A revoked attestation stays visible and is labeled, never deleted. A reference to an attestation that is not in the set is reported, not treated as invalid.

## Agent traces, usage and pricing (1.5.0)

- **Agent trace** (`trace_version` `1.0`, evidence type `agent_trace`): the steps of one run (`model_call`, `tool_call`, `a2a_call`) with token usage per model call, bound to the run by `execution` (`{execution_id, execution_digest}`). Prompts and outputs never appear; `io_digest` can commit to them. The schema is strict, so a trace with unknown fields is refused. Its digest is the canonical digest (`traceDigest`), so whitespace and key order do not matter. An evidence envelope's `content_digest` is still the sha256 of the file bytes.
- **OpenTelemetry import.** `traceFromOtelSpans` (TypeScript) and `trace_from_otel_spans` (Python) map an OTLP JSON export of GenAI spans (semantic conventions 1.41.0, which are at Development status) to a trace and list every span they skip, with the reason. `invoke_agent` spans become A2A calls only with the attribute `atcn.a2a.task_id`.
- **Run descriptors** gain optional `agent.additional_models` (requires `agent.model`). A trace may use only the declared models; a run that declares none allows any. The descriptor sits in open event `data`, so older consumers keep it as signed.
- **`agent_trace@1.0.0`** refuses, with a `code`: `malformed` (schema or rule failure: `seq` must increase, `ended_at` not before `started_at`, fields matching the step kind, cached tokens not above input tokens), `execution_not_declared`, `model_mismatch`, and `trace_outside_run` (a step before the run was declared or after evaluation).
- **Terms `schema_version` `1.2`** adds optional `pricing` (`rates` per meter: `input_tokens`, `cache_read_input_tokens`, `output_tokens`, `model_call`, `tool_call`, `a2a_call`; optional `fixed_minor`; `tolerance_bps`). Terms that set `pricing` must declare `1.2`, so a 1.4.x `@atcn/core` refuses them at the schema instead of dropping the field. `buildTerms` picks the version. Terms without pricing keep their bytes.
- **Pricing rules.** A rate naming the model or tool beats a general rate for the meter. `input_tokens` is priced as uncached input; cached tokens without a cache rate are priced at the input rate. A meter that no rate names is not charged; usage on a named meter that no rate matches is unpriced, and then no expected cost is computed. Each rate line rounds half up once. The allowed difference is `floor(expected × tolerance_bps / 10000)`. All arithmetic is exact integer arithmetic, identical in TypeScript and Python.
- **`usage_cost@1.0.0`** prices every admissible `agent_trace` covering the deliverable (each must pass the `agent_trace` rules; equal traces are priced once) and compares the result with the deliverable amount. An amount below usage cost passes, because the provider agreed to it; above it, the check fails beyond the tolerance with `usage_cost_mismatch`. Without pricing it refuses with `pricing_missing`; unpriced usage gives `usage_unpriced`. Results record `expected_minor`, `difference_minor`, `allowed_difference_minor`, `within_tolerance`, `trace_digests` and `lines_digest`.
- **Trace files offline.** `verifyClosurePackage` with `traces` (and `atcn-verify --trace`) rechecks each supplied trace against the declared runs and recomputes every `usage_cost` result from the terms' pricing. Without the trace files, the `trace_evidence` check reports "not inspected", which is neither a pass nor a failure.
- **`AGENT_USAGE_POLICY_V1`** (`agent-usage-checks@1.0.0`) requires `agent_trace` evidence and defines the checks `trace` and `usage_cost` alongside the code-change checks; each deliverable lists the checks it requires.

## Failure terms, finality, witnesses and conflicting attestations (1.5.0)

- **Terms `1.2`** also adds optional `refund_terms` and `witness_policy`; either requires `schema_version` `1.2`.
  - `refund_terms`: `on_failure` (`refund` or `dispute`; `dispute` needs a `dispute_reviewer_id`), `on_timeout` (must be `refund`, because the network expires an obligation at its deadline and pays nothing) and `after_settlement` (`cap_minor` up to `max_amount_minor`, `window_seconds` up to a year).
  - `witness_policy`: `min_independent_witnesses` (1 to 10), optional `witness_agent_ids` (none of them the issuer, the counterparty or the principal), and `independence: "distinct_verified_domain"`.
- **Clearing engine `atcn-clearing-engine@1.1.0`.** New reason codes: `failure_terms_dispute` (work rejected under `on_failure: "dispute"` goes to the reviewer), `conflicting_attestations` (the deliverable is disputed; the engine never picks a winner) and `witness_quorum_not_met` (insufficient evidence). Decisions recorded by `1.0.0` are replayed without attestation conflicts, so their digests are unchanged.
- **Settlement status `pending_finality`**: the rail reported the money as sent, but it can still be reversed. `RAIL_FINALITY` gives each adapter's `expected_seconds` and `max_seconds` (manual 0/0, sandbox 5/60, stripe 2/7 days); a payment pending past `max_seconds` should raise `finality_overdue`.
- **Witness attestations.** An `external_attestation` with `role: "witness"` must carry `execution` and `evidence_digests`. It is submitted as evidence type `witness_attestation` by a producer with role `witness`. On the subledger, a witness signs a response statement with `role: "witness"` through a link from `createWitnessShare` (TypeScript) or `create_witness_share` (Python).
- **`witness_quorum@1.0.0`** checks each witness attestation (subject, signer not a party and on the allowed list, key, signature over the bytes received, revocation at `issued_at`, declared run of the agreed skill, evidence on the obligation), drops revoked ones, and counts passing witnesses by verified registrable domain. Witnesses sharing a domain with a party do not count; witnesses sharing a domain with each other count once. Domains come from `verifiedDomainOf`, which the service supplies; the public packages compare lowercase strings and carry no public suffix list. Refusal codes: `no_witness_policy`, `independence_unverifiable` (a party has no verified domain) and `witness_quorum_not_met`. `WITNESSED_AGENT_WORK_POLICY_V1` (`witnessed-agent-work`) uses it.
- **Attestation conflicts** (`findConflicts`, `obligationAttestationConflicts`). Subjects are `<obligation>/<deliverable>/<check>` for verifier and witness attestations, and `<obligation>/execution:<id>` when the counterparty declares one run with two different descriptors. Kinds: `equivocation` (one signer, two statuses or runs), `disagreement` (two signers, two statuses), `execution_mismatch` (two runs) and `disputed` (a `disputes` ref in effect). Only attestations in effect at the decision time count.
- **Closure package `1.1`** adds `attestations` (the text behind every attestation-type evidence item) and `attestation_conflicts`. Producers emit `1.1` only when a package holds attestation evidence or a `pending_finality` settlement, otherwise `1.0`. `verifyClosurePackage` checks each text against its evidence digest and recomputes the conflicts (check `attestation_conflicts`), so removing a conflict or withholding a text fails after re-signing. 1.4.x verifiers accept only `1.0`; from 1.5.0, an unknown `package_version` gives `unsupported_schema_version` and `atcn-verify` exit code `3`.

## Estimates, signed outcomes, rail attestations and clearing verdicts (1.5.0)

- **Estimates and holds** are financial events with an `expectation` (`issued_by`, `source_ref`, `basis`, `expires_at`, `supersedes`, `hold_status`, optional `signer`). They never count toward net cost. A signed one carries the issuer's signature over the expectation statement (`atcn.subledger.expectation`), checked against a key binding of the issuer's provider. An estimate dated after the node's first charge, or recorded after it although dated earlier (unless `retrospective`), is `after_charge` and is not used. See [ESTIMATES.md](../../docs/ESTIMATES.md).
- **Provider-signed outcome claims.** `completion`, `partial_completion`, `cancellation` and `provider_failure` claims asserted by the provider may carry `signer` (`provider_id`, `binding_id`, `key_id`, `value`): the provider's signature over the outcome statement `{document_type: "atcn.subledger.outcome", type, provider_job_ref, occurred_at, note, evidence}`. The key must be bound to the delegation's provider and not revoked when the claim occurred; a signed claim cannot carry `usage`.
- **Rail attestations** (`{scheme, record}`) on `payment_reported` and `refund` events: `urn:a2a-se:escrow-release-attestation:v1` and `urn:a2a-se:escrow-refund-attestation:v1` (an A2A-SE attestation log record with its Merkle inclusion proof; the root is not signed, so compare `merkle_root` with the one the exchange publishes) and `x402:exact-evm:v2` (EIP-3009 authorization signed by the payer, with the facilitator's settlement response; this proves the payer authorized the transfer, not that it was included on chain). The importer's amount, currency and reference must match the event, or it is refused at intake.
- **Lineage.** Capture gap kind `broken_edge` records a reported sub-task that arrived with no outcome. The A2A adapter carries the chain of parent tasks in `metadata.atcn.lineage` and reported sub-tasks in `metadata.atcn.downstream`.
- **Clearing verdict** (`atcn.clearing.verdict`, `verdict_version` `1.0`, JSON Schema `clearing-verdict`): the obligation's decision in effect (latest decision not superseded) with its amounts, `final`, the named `escrow`, the `package_digest` of the closure package it was read from, and `stance: "record_only"`, signed by the service key. `verifyClearingVerdict` (and `atcn-verify` with `--obligation-package`) checks the signature and that the package verifies and states the same decision. ATCN only publishes the verdict; an escrow rail decides whether to release.
- **Reconciliation vectors.** [`packages/subledger/test-vectors/reconciliation.json`](../subledger/test-vectors/reconciliation.json) (double charge, cross-task replay, refund after close, charge after cancellation, back-dated estimate) with results in the settlement-conformance results shape in [`reconciliation-results.json`](../subledger/test-vectors/reconciliation-results.json).

JSON Schemas: [`schemas/1.2/`](schemas/1.2/), [`schemas/1.3/`](schemas/1.3/), [`schemas/1.4/`](schemas/1.4/) and [`schemas/1.5/`](schemas/1.5/). Each receipt response links the schema matching its own version.

- **Producers.** New receipt revisions and closure versions are signed as the newest version the producer supports. Documents already signed are never rewritten. A revision may link to a previous revision of an older version.
- **Verifiers 1.5.0 and later** accept `1.2` to `1.5` (1.4.x verifiers accept `1.2` to `1.4`; 1.3.x verifiers accept `1.2` and `1.3`). They check the version before anything else. Any other version gets one failing check, `schema_version`, plus `unsupported_schema_version` in the report and the message `unsupported schema_version X: this verifier (@atcn/subledger <version>) supports 1.2, 1.3, 1.4 and 1.5. Upgrade ...`. `atcn-verify` exits with code `3` for this case, and with `1` for an invalid document.
- **A document that declares an older version but uses newer fields** fails the `schema` check, because a verifier of that version could not read it. That includes `signed_by: "atcn-local-runner"` in `1.2`, and delegation `execution`, the new statement fields or the labels `expired` and `revoked` in `1.2` or `1.3`.
- **`1.5` fields in older versions** (pricing, usage, `usage_checks`, `delivery.usage`, `additional_models`, `refund_terms`, `witness_policy`, event `skill`, status `pending_finality`, statement `role`, estimates and holds, `expectation_report`, claim `signer`, `rail_attestation`, `rail_attestations`) fail the `schema` check of a document that declares `1.2`, `1.3` or `1.4`.
- **`1.5` checks.** A closure's `usage_checks` must equal what its delegations' pricing, counted usage claims (not superseded; a trace recorded twice counts once, from its latest claim), roll-up and responses produce; billed amounts may differ from expected cost in either direction only within the tolerance. Receipts and closures get a `trace_summary` check: with `traces` (`atcn-verify --trace`), each recorded usage summary is recomputed from its trace file; without them, it reports "not inspected". `delivery.usage` gets `provider_key_signed` only from an in-force signed attestation naming that field. A closure's `expectation_report` must equal what its estimates, holds, roll-up and key bindings produce. Check `signed_claims` re-verifies every provider-signed outcome claim against the listed key bindings, and only those may be labelled `provider_key_signed`. Check `rail_attestations` re-verifies every rail attestation offline (A2A-SE Merkle inclusion, x402 EIP-3009 signature) without contacting the rail. A `1.5` receipt lists `key_bindings`: exactly the bindings its signed claims, estimates and holds name, in `binding_id` order; check `signed_records` re-verifies those signatures. Check `open_exceptions` recomputes a `1.5` closure's derived exceptions as of `generated_at` and at close: each must be listed in `open_exceptions` or in `resolved_exceptions` (resolved or dismissed by a person, not `system`), matched on kind, delegation and detail, and every open derived exception must still hold. `witness_quorum_not_met` and intake exceptions are not recomputed. Closures declaring `1.2` to `1.4` pass it without recomputation, and may not carry `resolved_exceptions`.
- **`1.4` checks.** A receipt gets an `expiry` check: it fails once `expires_at` has passed (`atcn-verify --at <time>` checks against another time). In a closure, `provider_responses` also fails when a statement cites a run other than the one recorded on its delegation, has `expires_at` or `refs` without `issued_at`, expires before it was issued, was issued after the closure was generated, or revokes a statement its provider key did not sign; and when the `expired` and `revoked` labels do not match the statements as of `generated_at`. A reference to a statement outside the closure is a note on a passing check.
- **Who signed.** `issuer.signed_by` is `atcn-hosted-service` for documents from the hosted service and `atcn-local-runner` for documents produced on your machine by `atcn-local`. The local runner signs with a key it generates, so its documents prove internal consistency, not a third party's endorsement. Trust it only with the key file from the same run. `atcn-local-runner` was added to `1.3` without a new schema version because no verifier had been published before 1.3.0. Every released verifier accepts it.
- **1.3.0 is the first released verifier, and the 1.0.0 pre-release builds are withdrawn.** They were never published to a registry, and no package will be published as 1.0.0. Do not publish or distribute them: they lack the version check and would reject newer documents with a generic schema error. Every released verifier checks `schema_version` first. That check is covered by the test "names an unsupported schema version explicitly instead of failing on schema or signature", so a verifier meeting a future schema version always says it is unsupported and needs an upgrade.
- The Python SDK verifies receipts and closures (`verify_subledger_document`, with `obligation_packages` for the cross-check of obligation-backed delegations), closure packages `1.0` and `1.1` (`verify_closure_package`) and clearing verdicts (`verify_clearing_verdict`, which verifies the whole package) with the same checks and reports as TypeScript. The closure-package vectors (`packages/core/test-vectors/closure-packages.json`) cover all three. Python differs only on hostile input: it uses strict Ed25519 rather than ZIP-215, approximates `z.url()` with a scheme check, may break ties differently among 64 or more equal evidence candidates, and keeps `__proto__` keys. It also reproduces trace digests, usage summaries, expected costs and `usage_cost` details (`atcn.trace`), checked against the shared trace vectors. Response statements are unchanged in `1.3`. In `1.4`, `build_response_statement` takes the new optional fields and leaves them out when not given, so earlier statements keep their bytes; the shared test vectors cover both. In `1.5`, it takes `role` (`"witness"`) the same way, and the vectors include a witness statement.

## Releases

- Every npm package and the Python package share one version and are released together from a tagged commit (`v1.3.2`, ...).
- Every push to `main` that changes a package releases all of them at the next patch version. A MINOR or MAJOR release sets the version first (`npm run set-version -- 1.4.0`).
- A published version is never changed or reused. A bad release is fixed with a new version. The bad one is marked with `npm deprecate` or yanked on PyPI, never deleted and re-uploaded.

## Deprecation

- A field or event type is marked deprecated for at least one MINOR release before it can be removed in the next MAJOR release.
- The hosted service accepts the previous MAJOR for at least 6 months after a new MAJOR ships.
